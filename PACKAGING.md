# Build the worktrees from main

Keep the repository root on `main`. All packaging logic lives in `package.sh`
and `packaging/`; worktrees are read-only inputs. The A001 branch's `package.sh`
is not invoked. Each branch can still run independently with its original scripts.

```bash
./package.sh all --dry-run        # inspect detected worktrees and outputs
./package.sh A004 --setup         # prepare its environment, compile, verify, publish
./package.sh A001 A002 --setup    # select several tools
./package.sh all --setup         # build all four
./package.sh all                 # rebuild using prepared environments
```

The packager finds registered worktrees by their branch names. Both a project
folder inside the worktree and a flat project at its root are supported. The
fallback search directory can be changed with `--worktrees PATH`.
`--output PATH` changes the release root, but the default toolbox launchers always
use `small_toolbox_pub/tools`; use the default for toolbox integration.

```text
main/
  package.sh
  packaging/                         # compiler and per-project adapters
  Envsetup/requirements/             # tracked environment recipes
  Envsetup/environments/A001/.venv/   # ignored local runtime
  Envsetup/build/                     # ignored C/compiler intermediates
  tools/<project>/linux-x86_64/       # release: launchers, native modules, assets
  code/toolbox_linux/                 # UI discovery scripts
  .worktrees/A001/...                 # independent source branch
```

These are native **application-module releases**, using Cython and external
Python runtimes. They are not single-file, dependency-free executables. No
application `.py`, `.pyc`, generated C or worktree reference is needed at runtime.
Keep each complete release directory together; do not copy just its launcher.
Compilation does not prevent reverse engineering.

Each release is verified before publication. Build manifests include source
commit, dirty status, platform, Python version, installed packages and file hashes.
Changed sources need not be committed to build, but a dirty manifest is less
reproducible. Existing releases are preserved under timestamped `.backup-*`
folders; their edited configuration, input and output data stay in that backup.
Transfer any desired configuration/data to the new release after rebuilding.
Failed builds do not replace the currently published version. `all` attempts every
tool and exits nonzero if any fails; it is not an all-or-nothing release transaction.

## Launch

```bash
bash Envsetup/setup_env.sh
./run_toolbox_linux.sh
```

Refresh the UI after adding launchers. Each project has exactly one entry.
A001 and A003 open a new terminal in the complete release directory; no processing
starts automatically. Type `./podcast insert-speech`, `./podcast subtitle-only`, or
`./podcast translate-audio` for A001. For A003, type `./run --help` or
`./run --input PATH`. The shell stays open after a command completes.
A002 opens its browser UI; A004 opens the music player.

`./package.sh 001` is an alias for `./package.sh A001` (002–004 also work).
The release keeps its existing config/lib/input/output relationships, just like
A001_Pkg_EngAudioInsertChNTTS; the reference folder itself is not overwritten.
Terminal entries use `open-terminal` and `terminal.rc`, generated by the packager.
The runtime is selected by `podcast`/`run`; no global environment activation is needed.
For SSH or an existing terminal, use `./open-terminal --shell` from the release.
To choose a terminal emulator, set TOOLBOX_TERMINAL to an executable supporting -e.
Close the new terminal to end its shell; the toolbox log/Stop button is not a
reliable controller for jobs owned by an external terminal emulator.

Each release supports a smoke test without processing user documents:

```bash
tools/A004_QMeiaPlayer/linux-x86_64/run --self-check
tools/A001_EngAudioInsertChNTTS/linux-x86_64/podcast insert-speech --self-check
```

Set `QT_QPA_PLATFORM=offscreen SDL_AUDIODRIVER=dummy` when testing A004 without a
desktop. Self-checks validate imports/configuration/UI construction where supported;
they do not prove real playback, transcription, OCR quality, AI service access or
remote-worker behavior.

## A003 remote workers

Published A003 defaults to local execution and does not ship private remote hosts.
Remote mode can use separately prepared **source workers**, with
`RemoteSyncProject=0` and `RemoteSetupIfMissing=0`. The release refuses automatic
source synchronization/setup: the original rsync uses `--delete` and assumes source
files on workers. Deploy workers from the independent A003 source branch first.
Local subprocess workers are redirected to the release launcher.

## Distribution

Commit/review packaging scripts, Envsetup recipes, toolbox launchers and selected
`tools/` releases on main. Do not merge source branches into main. Large binaries
may instead be distributed as release archives. Copy the release plus main's
Envsetup recipes to another compatible Linux host, rerun environment deployment,
and keep the same directory layout. Windows application binaries and Android APKs
are outside this Linux packaging workflow.

## Verify releases

```bash
python3 packaging/verify_releases.py
```

This copies the releases to a temporary directory with spaces in its name, checks
all entry points, converts sample subtitles/books, and starts/stops A002's HTTP UI.
It uses installed environments but no source worktrees or user documents. Requires
Calibre for the conversion checks. Build staging and logs stay under Envsetup.
